# Plan Flow - PLAN.md 状态流转管理

管理根目录 `PLAN.md` 的状态流转，支持三个子命令。

## 子命令

### /plan-flow review
进入评审状态。适用场景：规划完成，需要另一个 agent 或人来 review 方案。

**执行步骤：**
1. 检查 `PLAN.md` 存在且非空（必须有"## 任务"section 且有内容）
2. 检查当前状态为"草稿"（如果已经是"评审中"或更后面的状态，拒绝并提示）
3. 将状态字段改为"评审中"
4. 提示用户："PLAN.md 已进入评审状态。请让评审者阅读 PLAN.md 并提出改进建议。评审完成后，使用 `/plan-flow execute` 开始执行。"

### /plan-flow execute
定稿并开始执行。适用场景：方案已确认（评审完或跳过评审），可以开始实施。可以从"草稿"或"评审中"任一状态直接进入，不需要区分"开始执行"和"执行完成"两个子状态——一旦触发，当前 agent 就应立即按步骤开始干活。

**执行步骤：**
1. 检查 `PLAN.md` 存在且必填字段完整：
   - "## 任务" section 有内容
   - "## 步骤" section 有至少一个步骤
   - "## 验收标准" section 有至少一条标准（`- [ ]` 格式）
2. 当前状态必须是"草稿"或"评审中"（如果已经是"执行中"，提示"已在执行中，无需重复调用"）
3. 将状态字段改为"执行中"
4. 提示当前 agent："PLAN.md 已定稿，请按照 '## 步骤' 中的内容执行。每完成一步建议 commit 一次。全部完成后，逐条核对 '## 验收标准' 并打勾（改成 `- [x]`）。验收通过后使用 `/plan-flow archive` 归档。"

### /plan-flow archive
归档当前计划并重置 PLAN.md。适用场景：代码已实施完成，验收标准已全部通过。

**参数：**
- `--todo=<任务简述>`（必需）：TODO.md 中对应的任务描述（用于自动更新 TODO.md）

**执行步骤：**
1. 检查当前状态为"执行中"（否则拒绝）
2. 检查所有验收标准已勾选（`- [x]`）：
   - 读取 "## 验收标准" section
   - 如果有任何 `- [ ]` 未勾选项，拒绝并列出这些项
3. 在 `TODO.md` 中找到与 `--todo` 参数匹配的任务行（在"## 进行中"section），移动到"## 已完成"section 顶部，格式：`- <任务简述> (完成于 YYYY-MM-DD)`
4. 将 `PLAN.md` 清空回初始模板：
   ```markdown
   ## 状态
   当前：草稿

   ## 任务
   （一句话目标）

   ## 背景 / 约束
   （相关上下文、红线、依赖；引用路径而非复制正文）

   ## 步骤
   1.
   2.

   ## 验收标准
   - [ ]
   ```
5. 提示用户："归档完成。PLAN.md 已重置，TODO.md 已更新。请 commit 这些变更（建议 message: `plan(archive): <任务简述>`）。历史计划可通过 `git log -p -- PLAN.md` 查看。"

## PLAN.md 状态字段格式

PLAN.md 必须包含以下状态字段（在文件开头）：

```markdown
## 状态
当前：草稿
```

允许的状态值：`草稿` | `评审中` | `执行中`

状态流转路径：
- 草稿 → 评审中 → 执行中（标准路径）
- 草稿 → 执行中（跳过评审的快速路径）

## 错误处理

- 如果 `PLAN.md` 不存在或为空，所有命令都应拒绝并提示"请先用 `/plan` 和 `/grill-with-docs` 创建计划"
- 如果状态流转违反规则（如从"执行中"回到"评审中"），拒绝并说明当前状态和允许的下一步
- 归档时如果找不到 TODO.md 中的匹配项，提示用户手动更新 TODO.md
